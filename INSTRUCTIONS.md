# Project Specification & Development Instructions: Wedding Snap & Share App

## 1. Project Overview
A static web application (HTML/CSS/JavaScript) hosted on GitHub Pages that allows wedding guests to enter their name and capture or upload up to 5 photos and/or videos in a single session. Media files are sent directly to an Amazon S3 bucket via presigned URLs generated by an AWS Lambda function.

---

## 2. Architecture & Components

```
[ GitHub Pages (Static Frontend) ]
       │
       ├─ (1) Request Presigned URLs ──> [ API Gateway ] ──> [ AWS Lambda ]
       │                                                          │
       ├─ (2) Receive Presigned URLs ─────────────────────────────┘
       │
       └─ (3) Direct Upload (PUT) ──────────────────────────────> [ Amazon S3 Bucket ]
```

---

## 3. Frontend Requirements (GitHub Pages Static Site)

### UI Flow & Structure (`index.html`)
1. **Welcome / Login Screen**: 
   - Clean, elegant wedding-themed UI.
   - Input field for the guest's **Name**.
   - "Start Capturing" button (disabled until name is entered).
2. **Capture / Upload Multi-Step Session (1 to 5 items)**:
   - Progress indicator showing current step (e.g., `Photo/Video 3 of 5`).
   - For each slot, provide options:
     - **Capture**: Open device camera (photo mode) or video recorder using HTML5 `getUserMedia` or file inputs with capture attributes (`capture="environment"`).
     - **Upload**: Select existing files from the device gallery (accepts images and videos: `image/*,video/*`).
   - **Preview & Confirmation**: Show a preview of the captured/uploaded photo or video.
   - **Controls**:
     - **Cancel / Retake**: Allows discarding the current selection and retaking/re-uploading before moving forward. The user **must** be able to cancel or retake before proceeding to the next capture/upload slot until all 5 files are completed.
     - **Next / Confirm**: Saves the current item to the session array and proceeds to the next slot until all 5 are completed.
3. **Review & Submit Screen**:
   - Thumbnails/previews of all 5 captured/uploaded files.
   - "Submit All" button.
   - Loading indicator with status updates during upload.
4. **Success Screen**:
   - Thank-you message and option to start a new session.

### Technical Frontend Details (`app.js`)
- **Hosting**: Pure HTML, CSS (Tailwind CSS via CDN or custom styling), and vanilla JavaScript. No complex build tools required, making it ideal for direct deployment to GitHub Pages.
- **Workflow**:
  1. Collect guest name and sanitize it (e.g., remove spaces/special characters for file naming).
  2. Gather up to 5 File/Blob objects into an array.
  3. Call the API Gateway endpoint with metadata (guest name, file extensions/types, count = 5).
  4. Receive 5 S3 presigned PUT URLs from the Lambda response.
  5. Iterate through the files and upload each directly to S3 using `fetch(presignedUrl, { method: 'PUT', body: file, headers: { 'Content-Type': file.type } })`.
  6. Display success feedback.

## 4. Backend Requirements (AWS Lambda & API Gateway)

### Naming Convention Logic
Each uploaded file must follow this exact naming format:
`[SanitizedUserName]_[8-Char-Alphanumerical-Code]_[Counter].[ext]`
- **`SanitizedUserName`**: User's name with spaces removed/hyphenated and special characters stripped.
- **`8-Char-Alphanumerical-Code`**: A randomly generated time-based or cryptographic 8-character alphanumeric string generated per session (e.g., `A4F9K2M1`).
- **`Counter`**: A suffix number from `1` to `5` corresponding to the file index.
- **`[ext]`**: Original file extension (e.g., `.jpg`, `.mp4`).

*Example:* `JohnDoe_A4F9K2M1_1.jpg`, `JohnDoe_A4F9K2M1_2.mp4`

### Lambda Function (`lambda_function.py`)
- **Input Payload**: Receives a JSON body containing `name` and an array of file extensions/types (e.g., `fileTypes: ['image/jpeg', 'video/mp4', ...]`).
- **Process**:
  1. Generate the unique 8-character alphanumeric session code.
  2. Loop through the requested files (up to 5).
  3. Generate the specific file key (filename) using the naming convention.
  4. Use the AWS SDK (`boto3` for Python) to generate a `put_object` presigned URL with an expiration time (e.g., 300 seconds).
- **Output**: Return an array of presigned URLs and their corresponding S3 object keys.

### API Gateway Configuration
- Create an HTTP API or REST API in AWS API Gateway connected to the Lambda function.
- Enable **CORS** to allow requests from your GitHub Pages domain (`https://<username>.github.io`).

## 5. AWS S3 & Security Configuration

1. **S3 Bucket Setup**:
   - Create a private S3 bucket.
   - **CORS Configuration**: Configure CORS on the S3 bucket to allow `PUT` requests from your GitHub Pages origin:
     ```json
     [
       {
         "AllowedOrigins": ["https://<your-github-username>.github.io"],
         "AllowedMethods": ["PUT"],
         "AllowedHeaders": ["*"],
         "MaxAgeSeconds": 300
       }
     ]
     ```
2. **IAM Permissions**:
   - Ensure the Lambda execution role has permissions to call `s3:PutObject` on the target bucket.
